# Скиллы

Скилл — это записанная инструкция, которую агент выполняет для повторяющейся задачи, чтобы каждый раз не объяснять заново. По сути — сохранённый промпт с протоколом. Роли (`ROLES.md`) — это тоже скиллы, просто самые крупные и постоянные.

**Как использовать.** Дай агенту прочитать нужный файл и скажи, например, «подготовь к встрече с X по скиллу meeting-prep» или «собери недельный дайджест». Агент следует протоколу.

**Как заводить свои.** Заметил, что раз за разом просишь одно и то же (собрать prep, свести отчёты, проверить свежесть статусов) — опиши это одним файлом: задача, когда запускать, протокол по шагам, что на выходе, чего не делать. Держи скилл коротким и конкретным.

## Подключение и происхождение

**У скилла один оригинал в системе.** Приложение агента читает его через ссылку на основное дерево системы или по пути из реестра. Отдельную копию в папке скиллов агента не веди: она быстро разойдётся с оригиналом. Калибровки и исправления вноси в оригинал; профиль письменного голоса хранится так же.

В начале файла скилла, в том числе `SKILL.md`, укажи YAML-фронтматтер с `name` и `description`. В описании перечисли общие триггеры, по которым агент должен прочитать инструкцию:

```yaml
---
name: <название-скилла>
description: <задача и формулировки запросов, при которых читать скилл>
---
```

В основном файле инструкций агента заведи **реестр «название / путь / когда читать»**. Путь должен вести к оригиналу и быть доступен приложению. Проверь подключение: попроси агента прочитать файл и назвать его задачу. **Без подключения или строки в реестре агент скилл не увидит.** Один фронтматтер доступ к файлу не создаёт.

**Рядом со скиллом держи `README.md` с провенансом:** откуда собран метод, из какого материала, какие ограничения и известные дефекты остались. Для одиночных файлов общий провенанс можно вести в этом `README.md`, отдельным блоком для каждого скилла. У профиля голоса собственный `README.md` обязателен: при настройке запиши в нём происхождение корпуса и результат ручной приёмки. Не публикуй сами сообщения и личные ссылки. Чужую инструкцию нельзя переносить без права на распространение; общий метод описывай своим текстом.

## В наборе для старта

- `meeting-prep.md` — подготовка к встрече (шпаргалка твоего уровня).
- `meeting-digest.md` — разбор встречи: превращает сырую стенограмму в структурированное знание (9+2 слоя, контр-эвристика пропусков, план переноса до действий). Полный протокол роли «Разборщик встреч».
- `meeting-mirror.md` — взгляд с той стороны стола: что сказал бы собеседнику его собственный агент про тебя. Только для встреч, где кроме тебя 1–3 участника; запускается после разбора.
- `weekly-digest.md` — недельный пульс направления на один экран.
- `self-mirror.md` — зеркало дня: ежедневный срез про твой управленческий стиль.
- `transcribe.md` — локальная транскрипция, проверка записи и передача в общий разбор встречи.
- `presentation-builder.md` — сборка презентации из проверенных фактов в одиночный HTML.
- `presentation-review.md` — проверка презентации глазами адресата до сходимости с ограничением числа кругов.
- `my-writing-style/` — метод сборки письменного голоса и пустой шаблон профиля `profile-template.md`.
- `recurring-meeting.md` — подготовка и разбор серии встреч руководителей, закрытые темы и проверка поручений.
- `monthly-report.md` — ежемесячный отчёт руководителю, сопоставимость показателей и записка докладчику.
- `agent-orchestration.md` — необязательный продвинутый слой координации агентов с доказательствами и независимым ревью.
- `human-voice/` — финальная проверка текстов наружу на признаки машинного письма: каталог приёмов, порядок прохода и скрипт `lint.py`, который находит механические признаки.
- `decision-analysis/` — скилл «анализ решений руководителя» + шаблон твоего свода управленческих принципов: прогоняет решение через твои принципы, помечает согласование, конфликты и слепые зоны.
- `b24-bridge/` — мост к порталу Битрикс24 (многослойный сенсор). `SKILL.md` — фундамент: подключение вебхука, безопасность, транспорт, базовые рецепты (люди / календарь / задачи / оргструктура / чаты). Рабочие слои рядом: `chat-sweep.md` (прочёс чатов всех видов — личка, группы, каналы, чаты задач и проектов, за период), `followups.md` (разбор AI-фоллоу-апов звонков), `work-reports.md` (свёртка рабочих отчётов), `write-path.md` (поставить задачу, в том числе сразу в колонку канбана / перенести карточку / закрыть задачу / отправить сообщение / создать групповой чат / прокомментировать задачу — по протоколу подтверждения; исключение «задача на себя» только твоей настройкой; что делать, если ответ на запись не пришёл), `mcp-facade.md` (продвинутый путь: обернуть мост в локальный MCP-фасад, когда он стал ежедневным инструментом).
